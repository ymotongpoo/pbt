# 例題: 『プロパティはどう思いつくのか』（現在執筆中）

このディレクトリには、山口能迪『プロパティはどう思いつくのか　プロパティベーステスト発見ガイド』（現在執筆中、書名は未確定）の例題をGoに移植したコードがあります。
本の例題は[fast-check](https://fast-check.dev/)とVitestを使ってTypeScriptで書いたものが正式で、このディレクトリのコードはそれを `go.ymotongpoo.com/pbt` に移したものです。
この本の主題はライブラリの使い方ではなく、プロパティの見つけ方です。
各章は仕様から出発してプロパティを導き、そのプロパティが仕込んだバグを捕まえることを確かめます。

## 実行のしかた

`examples` ディレクトリでテストを実行します。

```sh
go test -race ./discovery/...
```

名前が `Mutant` で終わるテストは、仕込んだバグに対してプロパティを実行するもので、失敗するのが正しい結果です。
テスト全体を通る状態に保つため、これらのテストは環境変数 `PBT_MUTANTS` がなければスキップします。
`run_mutants.sh` は通常のテストを実行してから、変異のテストを1本ずつ実行し、通ってしまった変異を報告します。

```sh
./discovery/run_mutants.sh
```

1つの変異の報告を読むには、そのテストを直接実行します。

```sh
PBT_MUTANTS=1 go test -run '^TestRuneExactEmptyMutant$' ./discovery/ch02
```

スケジュールに依存するテストや、多数回の実行で検出率を計測するテストは、`PBT_FLAKY=1` や `PBT_MEASURE=1` がなければスキップします。
第16章の、レースディテクターでだけ失敗する変異は `-race` を付けたときにビルドされます。

コード中のコメントとメッセージは、本と同じく日本語です。

## 本と対応しない箇所

プロパティ、仕込んだバグ、表の検出と通過の判定は、ほとんどの章で本と同じです。
割合、ケース数、縮小した反例のように生成器に左右される数値は、fast-checkとpbtの生成のしかたが違うので、本とは一致しません。
コマンドはpbtの方式で書いています。列全体をモデルに対して先に生成し、まだ実行していない結果を `Var` で指す方式です。
本は、モデルとともに実行しながら進むfast-checkのコマンドで説明しています。
次の5か所は本の側をfast-checkに合わせて書き換えたので、このディレクトリのコードとは対応しません。

1. **第2章のステップ5**（`ch02_test.go` の `TestTruncateCoverage`）。
   ここでは `pbt.String()` と `IntRange(0, 20)` のまま `CheckCoverage` を満たして通ります。
   本では、`fc.string()` が10文字までの文字列しか作らないので、同じ要求が未決のまま失敗します。
   本はその報告を示し、生成器を直します（サロゲートペアを含む文字の集合、`n` は0から10）。
2. **第9章の割合の計算**（`ch09/` の `Percent`）。
   ここでは `int` の掛け算 `done*100` が溢れます。
   JavaScriptの数値は倍精度で溢れないので、本は32ビットに切り詰める `Math.imul(done, 100)` で溢れを作っています。
3. **第15章の重みの調整**（`ch15/`）。
   ここでは `new` の自己遷移が1%未満なので、`new` から出る遷移の重みを verify 1、lock 2、unlock 2 に変えます。
   本では列が10手までと短く、この遷移は8%前後あります。
   最も低いのは `locked` の自己遷移なので、本は `locked` から出る遷移の重みを unlock 1、verify 2、lock 2 に変えています。
4. **第16章の並行テスト**（`ch16/`）。
   ここでは `pbt.ParallelCommands`（逐次の前段と並行の枝、線形化可能性の検査）と `go test -race` で章を組み立てています。
   JavaScriptにはスレッドがないので、本は `await` をまたぐ非同期の操作の交互配置を `fc.scheduler` で作り、線形化可能性は本の中で書いた補助関数で調べます。
   そのため、次の点が違います。
   - データ競合とレースディテクターの節（`stat_race_test.go` と `stat_norace_test.go` の `StatCounter`、ロックのない版、`-race` との比較表）は本にありません。
   - ここでのカウンターは、読み出しと書き込みで別々にロックを取り、その間に他のゴルーチンが割り込むと更新を失います。本では、読み出しと書き込みの間の `await` で更新を失います。
   - `StickyRegister` は、ここでは線形化可能性の検査を通り、章は別の手段が必要だと結論します。本は呼び出しと完了の前後を記録し、実時間の順序を見る検査で捕まえます。
   - 再現しにくい失敗の節は、ここでは保存したケースの再実行と `-race` を扱います。本は、交互配置が生成された値の一部になること、`seed` と `path` による再実行、`schedulerFor` を扱います。
5. **第19章の過去のバグ**（`ch19/`）。
   本では、pbt自身のv0.3.2の修正（`Rune` がU+10FFFFを含むようになった）を例にした段落と、`examples/practical` を案内する段落を削りました。
   どちらの段落にも、このディレクトリに対応するコードはありません。
   また本は、見つけた反例をfast-checkの `examples` オプションで残します。pbtが `testdata/pbt` に保存する失敗のファイルは使いません。
